# Architecture

One Next.js app, one Postgres database, one daily job. No queues, no microservices, no state library.

```
Browser ──► Next.js (App Router, Vercel)
              ├─ pages (React Server Components + client components)
              ├─ /api/trpc      tRPC routers ──► Drizzle ──► Postgres (Neon)
              ├─ /api/auth      Better Auth
              └─ /api/cron/daily  ◄── Vercel Cron, once a day
                     ├─► dps.psx.com.pk        (stock prices)
                     └─► GitHub raw dataset    (fund NAVs)
```

## Stack

| Concern | Choice | Why |
| --- | --- | --- |
| Framework | Next.js App Router, TypeScript | T3 default |
| API | tRPC v11 + TanStack Query | End-to-end types, no hand-written fetch code |
| DB | PostgreSQL (Neon) + Drizzle | T3 default; exact `numeric` type for money |
| Auth | Better Auth, email + password | Offered by the T3 CLI; supports disabling sign-up |
| Styling | Tailwind v4 + shadcn/ui | CSS-variable theming fits the Mercury light/dark tokens |
| Charts | MUI X Charts | Themed from the same tokens through a small MUI theme bridge |
| Forms | react-hook-form + Zod | The same Zod schema validates the form and the tRPC input |
| Tests | Vitest, for the calculation library only | Money math must be right; the rest is checked by hand |

Deliberately left out: TanStack Table (plain tables with a sort toggle are enough), a state manager, an animation library, a second component library.

## Data model

Own tables use an integer identity `id`. Every own table has `userId` (text, FK to the Better Auth user, cascade delete) and every query filters on it.

Money columns are `numeric(18,2)`. Units and unit prices are `numeric(18,4)` (fund NAVs have four decimals). Drizzle reads them with `mode: 'number'`; personal amounts are far inside safe floating-point range, and results are rounded to 2 decimals at the edges.

All dates are plain `date` values in Pakistan time. No timestamps in business data.

### Auth tables

`user`, `session`, `account`, `verification`: generated by the Better Auth CLI. Not edited by hand.

### `asset`: one row per holding or account

| Column | Type | Notes |
| --- | --- | --- |

| `name` | text | Company, fund or account name |
| `symbol` | text, null | PSX ticker (stocks only) |
| `fundId` | text, null | MUFAP fund id (funds only) |
| `institution` | text, null | Broker, AMC or bank |
| `lastPrice` | numeric(18,4), null | Latest price or NAV. Null for savings |
| `priceAsOf` | date, null | Date the price is valid for |
| `priceSource` | enum `auto`, `manual`, null | |
| `profitRate` | numeric(5,2), null | Savings: annual rate, for display only |
| `notes` | text, null | |

Index: `(userId, kind)`.

### `asset_txn`: every movement

| Column | Type | Notes |
| --- | --- | --- |
| `assetId` | FK → asset, cascade | |
| `kind` | enum `buy`, `sell`, `bonus`, `dividend`, `deposit`, `withdrawal`, `profit` | |
| `date` | date | |
| `units` | numeric(18,4), null | Shares or fund units |
| `unitPrice` | numeric(18,4), null | |
| `amount` | numeric(18,2) | Gross PKR. `units × unitPrice` for buy/sell; cash for the rest; 0 for bonus |
| `fees` | numeric(18,2), default 0 | Commission, taxes, load |
| `notes` | text, null | |

Index: `(assetId, date)`.

Allowed kinds: stocks and funds use `buy`, `sell`, `bonus`, `dividend`. Savings use `deposit`, `withdrawal`, `profit`. The API rejects anything else. `bonus` covers bonus shares and reinvested fund dividends (units arrive at zero cost).

### `portfolio_snapshot`: one row per day per asset kind

`(userId, date, kind)` primary key, `marketValue`, `costBasis`. Written by the daily job. Feeds the net-worth chart. No per-asset price history is stored.

### `expense_category`

`name`, `color` (a chart token name). Unique `(userId, name)`. Seeded: Subscriptions, Payments to people, Food, Transport, Bills & utilities, Shopping, Health, Family, Other. A category in use cannot be deleted, only renamed.

### `subscription`

| Column | Type | Notes |
| --- | --- | --- |
| `name` | text | Service name |
| `amount` | numeric(18,2) | |
| `categoryId` | FK → expense_category | Default: Subscriptions |
| `cycle` | enum `monthly`, `yearly` | |

Index: `(userId, status)`.

**Mark paid** (one database transaction): insert an `expense` with the subscription's category, name and the amount actually paid; then move `nextDueDate` forward one month or year. Expenses are never created automatically; a payment exists only when you confirm it.

Money given to someone has no table of its own. It is an ordinary `expense` in the "Payments to people" category.

## Portfolio math (`src/lib/portfolio.ts`)

Pure functions, no database access, covered by unit tests. Average-cost method, transactions processed in date order.

| Transaction | Effect |
| --- | --- |
| `buy` | `units += u`; `cost += amount + fees` |
| `bonus` | `units += u`; cost unchanged |
| `sell` | `avg = cost / units`; `realized += (amount − fees) − avg × u`; `cost −= avg × u`; `units −= u`. Selling more than held is an error |
| `dividend` | `income += amount` |
| `deposit` | `balance += amount`; `invested += amount` |
| `withdrawal` | `balance −= amount`; `invested −= amount` |
| `profit` | `balance += amount`; `income += amount` |

Derived per asset: `marketValue = units × lastPrice` (savings: `balance`), `unrealized = marketValue − cost`, `unrealizedPct`, `avgCost`. When a unit asset has no price yet, market value falls back to cost and the row is flagged "no price".

Totals per kind and overall are sums of the above; allocation is each kind's share of total market value.

## API (tRPC routers)

All procedures are `protectedProcedure`. Inputs are Zod schemas shared with the forms.

| Router | Procedures |
| --- | --- |
| `asset` | `list({kind})` with computed positions and totals, `get`, `create`, `update`, `delete` |
| `assetTxn` | `list({assetId})`, `create`, `update`, `delete` |
| `price` | `refresh({kind?})`, `setManual({assetId, price, date})`, `lookupStock({symbol})`, `searchFunds({query, moneyMarket})` |
| `expense` | `list({month})`, `summary({month})`, `trend()`, `create`, `update`, `delete` |
| `category` | `list`, `create`, `rename`, `delete` |
| `subscription` | `list`, `create`, `update`, `delete`, `markPaid`, `setStatus` |
| `overview` | `get()`: net worth, allocation, snapshot series, month spend, upcoming subscriptions, top holdings |

## Prices

```
refreshPrices(userId, kind?)
  for each asset with a symbol or fundId:
     stock → psx.fetchPrice(symbol)
     fund  → funds.fetchNav(fundId)
     success → update lastPrice, priceAsOf, priceSource = auto
     failure → leave the row unchanged, collect the error
  return { updated, failed: [{asset, reason}] }
```

- **Stocks** (`prices/psx.ts`): fetch `dps.psx.com.pk/company/{SYMBOL}`, read `.quote__close` with cheerio. If that fails, try the JSON endpoint `/timeseries/int/{SYMBOL}`. Requests run one at a time with a short pause, and a successful quote is cached for five minutes.
- **Search** (`prices/symbols.ts`): a bundled directory of 468 listed companies (`psx-symbols.json`, refreshed with `pnpm psx:sync`), matched on symbol first and then on company-name tokens. No network.
- **Funds** (`prices/funds.ts`): fund list from `funds.json` (cached for 12 hours); NAV from the last line of `history/{fundId}.ndjson`, falling back to the 2-decimal NAV in `funds.json`.
- **Manual**: the edit dialog can always set a price by hand. A manual price is overwritten by the next successful automatic refresh.
- **Refresh button**: calls the same function. The server skips any asset refreshed in the last 10 minutes, so repeated clicks do not hammer the sources.
- **Staleness**: a price older than 3 days gets a visible "as of {date}" warning tag.

See research.md for what was tested and the terms-of-use caveat.

## Daily job

`GET /api/cron/daily`, guarded by `Authorization: Bearer $CRON_SECRET`.

1. `refreshPrices` for all assets.
2. Compute positions and upsert one `portfolio_snapshot` row per asset kind for today (Pakistan date).
3. Return a JSON summary of updates and failures.

Schedule: `0 18 * * *` UTC, which is 23:00–23:59 in Pakistan: after the PSX close and after the fund dataset's evening update. The job is safe to run twice.

## Auth and security

- Better Auth with email + password. Sign-up is disabled unless `AUTH_ALLOW_SIGNUP=true`, which only `scripts/create-user.ts` sets.
- `proxy.ts` redirects to `/login` when there is no session cookie. This is a convenience only.
- The real checks: `(app)/layout.tsx` validates the session on the server, and every tRPC procedure is protected and scoped by `userId`.
- Better Auth rate limiting is enabled for the sign-in route.
- The cron route rejects requests without the secret.
- The whole site is `noindex`. The only public page is `/login`.
- Secrets live in environment variables, validated at startup by the T3 env file.

## Hosting

**Recommended: Vercel (Hobby) + Neon.** Zero server upkeep, automatic deploys from Git, built-in daily cron, free at this scale. `fin.devshub.xyz` is a CNAME record pointing at Vercel.

With Neon's pooled connection string, postgres.js needs `prepare: false`.

**Alternative: your own VPS.** Run `next start` (or Docker) behind Caddy or Nginx, with Postgres on the same machine, and a system cron that calls `/api/cron/daily` with the secret. The application code is identical. Choose this if PSX turns out to block Vercel's servers (tested in Phase 5) and you have a server in Pakistan.

## Backups

Neon keeps point-in-time history for a limited window on the free tier. Phase 10 adds a `pg_dump` command to the project README for an occasional manual backup.
